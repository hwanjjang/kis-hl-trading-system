# Investigation
Read 2026-09-22. Official order-types page lists continuous mark-based perp trailing with quote/percentage retracement. Public exchange docs and official Python SDK lack a dedicated helper.
Official app config-DWLPMyx3.js ace() constructs ordered action: type=trailingStop, asset, isBuy, sz (decimal string), reduceOnly, retracement={pct:"5.0000%"} or {px:"..."}, activationPx=null/string. mce() sends through I6/Uoe to /exchange; ws() signs the standard L1 Agent payload with optional expiresAfter. No cloid in this observed action. The app tests status=err; it does not prove an oid response contract. Unrecognized success must remain unknown.
App bM order schema contains oid, coin, side, sz, origSz, reduceOnly, isTrigger, orderType, triggerCondition. Order types include Trailing Stop Market. s4/l4 parse retracement, best and optional activation from triggerCondition. Generic open-orders cancellation uses standard cancel by asset/oid. Retain source hash in app-evidence.json; app download in /tmp is research input, not a shipped vendor bundle.
Implementation implication: use official SDK generic L1 signing and post, SDK-owned asset IDs; strict protective readback and known native ID required. No matching by size/time to adopt potentially foreign orders. Keep native fixed SL throughout. Wait until entry terminal before adding trailing, so late fills cannot be left outside the native trail. No automatic re-creation after cancellation (would reset watermark).
