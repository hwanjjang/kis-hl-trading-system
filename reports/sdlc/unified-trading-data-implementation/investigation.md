# Implementation investigation
Existing `JournalLedger` stores exact-time fills and immutable cycle revisions, but funding IDs currently concatenate hash and coin; zero-hash events collide. Existing market tables upsert daily bars without revision history. Clients already expose Hyperliquid candles/book/funding and KIS daily/index/stock charts and quotes. Private KIS source files include daily settlement rows, while generated journals are derived baselines only. Private tradefi source files include fill and daily-aggregated funding lists. Account identity and source grain must come from an explicit manifest, never filenames alone.

Implementation uses compact shared `fact_revisions` storage with dataset-specific validated payloads instead of materializing every proposed table up front. Account/market indexes, relational provenance, coverage, reports and jobs remain explicit. Legacy trading state stays separate; canonical consumers are exposed through new CLI commands, with existing writer bridges documented and tested. No active database replacement or assumed ten-year API guarantee.
