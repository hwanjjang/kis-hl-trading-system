# Specification
Plan gains trailing_provider=local|native (default local); native restricted to catalogued Hyperliquid perps. Local policy unchanged. Native management freezes ATR quote distance, activation immediately; fixed entry SL retained independently. Low-level method supports protective buy/sell, quote or percent retracement, optional activation; always reduceOnly. Reject nonfinite/invalid values, unsupported assets, stale verification, invalid precision, missing credentials and invalid environment before signed I/O.
Persist a trailing attempt before a single transmission after terminal entry and verified full fixed-SL coverage. Read trailing only by acknowledged native oid. Missing oid is unknown and blocks automatic resubmission/adoption. Strict readback matches coin, oid, side, reduceOnly, type, requested retracement and valid best mark; unknown condition formats claim zero trailing coverage; independently verified fixed SL remains supervised. An acknowledgement alone never counts as coverage. A previously accepted terminal native trail latches exit of remaining exposure. A rejected submission is not an established watermark. Restart never resets exchange watermark. Ordinary reduction may leave oversized reduce-only protection; flat cleanup cancels both stop kinds and requires terminal readback.
No schema migration: plan/attempt/position snapshots already JSON. Diagnostics expose separate trailing coverage and provider. Existing plans with no selector remain local. Rollback: preserve existing managed records, do not silently switch active policy. Operator reconciles and closes native positions before reverting code.

## Corrective contract
- Normalize frozen ATR quote distance using metadata decimal precision and the distance's own significant figures (integers remain allowed). Persist it on the managed row before any entry. Reject zero normalization before entry. Existing in-flight records without the field calculate it from current metadata before their first trail, without resending existing attempts.
- No oid or rejected trailing submission: INTERVENTION, no automatic retry/adoption, retain and monitor fixed SL. This specific intervention may still process explicit exit requests, fixed-SL loss and cleanup; unrelated reconciliation failures remain frozen.
- Verified open full-sized waiting order (best waiting or missing best): zero active trailing coverage, remain PROTECTING, no timeout exit solely for waiting. Continue normal fixed-SL and terminal-order handling; active readback moves to PROTECTED, including after restart.
- Parse retracement (quote/percent), optional activation above/below and optional best independently. Reject duplicate, unknown, nonfinite and malformed clauses. Managed readback accepts only the requested quote distance and immediate activation; percentage or explicit activation remains a semantic mismatch, not a grammar error.

Clarification: rejection of a submission without an acknowledged order ID is distinct from a later rejected status on an accepted known-ID trail. The latter is terminal and retains residual-exit handling.

## Isolated condition errors
A dedicated TrailingConditionError represents condition parse failure only. Gateway records trailing_readback_error on the known order and completes otherwise strict account reconciliation. No active coverage is inferred. Supervisor marks native-specific INTERVENTION, retains SL supervision and explicit exits, and never resubmits/adopts. A valid matching same-ID readback clears this marker and restores waiting/active state; an acknowledged terminal order exits residual exposure even if its condition cannot be parsed. Flat cleanup still uses verified identity. Ordinary identity/type/side/size/known-policy mismatch and inconsistent account evidence remain fatal. Generic INTERVENTION transitions clear the marker; snapshot transport failures explicitly preserve it for subsequent recovery. No changes to live flags or network defaults; no schema migration.

## Native primary and queued manual adoption (supersedes new-plan default)
New Hyperliquid perpetual plans normalize omitted trailing_provider to native; KIS defaults local. Explicit local is the auxiliary alternative. Existing persisted rows, including missing-selector legacy rows, retain local semantics until an explicitly new plan; no policy migration or competing automatic local/native exits.
CLI `order adopt --input PLAN --entry-order-id OID --stop-order-id OID [--live]` queues ADOPTING with explicit identity. Same plan risk fields are required, with quantity and limit_price matching actual position quantity and average entry. Without --live, supervisor marks PREVIEWED and performs no exchange I/O. Harness/source intent metadata is retained. Signal/grant IDs cannot be smuggled through adoption.
Live supervisor validates a fully filled single long entry, complete account fill history from its timestamp, no additions/reductions or foreign open orders, exact entry quantity/average, allowed asset/precision, current ATR and quote, portfolio/risk limits, and an existing full-sized native fixed SL at or above risk floor. Imported entry and SL must have distinct positive native IDs. Reject conflicting active managed/legacy ownership or previously imported/submitted entry IDs. Store imported terminal entry and open SL attempts, history start, actual fill time, frozen distance, ATR provenance and adopted_ms atomically before any trailing transmission. No external write occurs during admission.
On next poll normal supervisor reconciles again, then submits at most one native trail after verified SL; explicit local instead starts at adoption with no historical high reconstruction. Preserve fixed SL, condition-error isolation, unknown-outcome handling, exit deadlines and flat cleanup. Rejected admission stays INTERVENTION with no imported attempts and requires recover -> ADOPTING; cancel/exit before admission cancels the handoff only. No code path may submit a new entry for an adoption record. Imported orders retain original journal attribution, while newly transmitted protective/exit orders can be attributed to the harness management policy. No schema migration: JSON additions are optional. Existing legacy worker remains explicitly local and is not run concurrently on the adopted asset.

### Confirmed concurrent local backup (supersedes alternate-only assumption)
For newly validated native Hyperliquid plans, local_trailing_backup is a boolean defaulting true; false explicitly disables backup. It is invalid to enable this field for a local provider. Supervisor ticks the existing local nine-minute Trail whenever local provider or native+backup is selected. A local hit persists the existing reduce-only exit intent; native orders and fixed SL remain while residual exposure exists, then terminal readback governs cleanup. No second worker, new native submission, policy switch or watermark reset occurs. During native-specific intervention the local backup remains eligible; generic account/identity intervention still freezes all automation. Native waiting/active readback does not clear a latched local exit. Existing persisted rows missing local_trailing_backup retain prior behavior. State/status exposes providers.local_trailing_backup. New default is native plus concurrent local, KIS local unchanged.
